# AWS に上げるまでに検討すること

状態: **検討中**（2026-11-08。環境を用意する段階で、Claude に構成のアドバイスを求める。それまで着手しない）

## 背景
ローカル版（②Web 化の前）は完了（G5 通過・本番の収集 1 回実行済み）。AWS で個人向けに常時公開し、毎朝 6 時に自動で収集する。
現在は `make dev` でローカル起動、更新は画面のボタン（別プロセス）または `make collect`。

## 検討項目（推奨順）
1. **認証**: 今は誰でも開け、更新ボタンも押せる。更新は Haiku の費用が発生するため、ログイン（自分だけ入れる）は必須
2. **API キーの置き場所**: 今は `../.secrets/.env`。Secrets Manager 等へ移す
3. **DB の置き場所**: SQLite は再デプロイ・複数台で消えやすい。1 台構成＋ボリューム＋バックアップか、RDS か（個人用なら前者が安い）
4. **実行基盤**: 更新を別プロセスで起動する今の仕組み（`run_launcher`）は使えない。ECS タスクか Lambda を EventBridge で起動する形にし、画面の「更新」ボタンも合わせる。収集は数分かかるので Lambda の 15 分制限を確認
5. **月額の費用**: Haiku は月 $10 の上限を設定済み。AWS 側の固定費（サーバー・DB・通信）を見積もる
6. **収集の礼儀**: サーバーの IP が変わる。robots.txt の遵守に加え、アクセス拒否が増えないかを再測定。ブラウザでの取り直し（Chrome）もサーバーに入れる必要がある
7. **監視と通知**: 収集の失敗・費用の超過に気づく仕組み（今は画面の実行履歴だけ）
8. **ログ**: `data/logs/` を CloudWatch に出すか

## 次の一手
aws-docs の MCP を有効にして（`.claude/settings.json` の `disabledMcpjsonServers` → `enabledMcpjsonServers`）、1（認証）と 4（実行基盤）の構成案の比較表を作る。
