> このファイルは**今の仕様だけ**を書く。変わったら書き換える（履歴は `.steering/history.md`）。
> 最終更新: 2026-11-08（画面・DB・API・収集・話題のまとめ・採点・選定・整理記事・更新ボタン・壁打ち・好みメモと修正案まで）

## 概要
生成AIの記事を集め、好みで選定し、関心に沿って整理した日本語の記事を、ダッシュボードで見る個人用アプリ。
設計の全体は `.steering/20261107-local-dashboard/design.md`。

**実装済み**: 7シートの画面、DB（表・移行・全文検索・バックアップ）、API、記事の収集（本文の取得まで）、話題のまとめ、Haiku による採点、選定、費用の上限。
**未実装**: 定時の自動実行（②Web 化のとき）。
`make seed` で試しの架空のデータを入れて画面を確認することもできる。

## 画面
| パス | シート | 内容 |
|---|---|---|
| `/` | 最新トピック | 直近7日の選定記事を、更新の回ごとに点数順で並べたカード。重大ニュースは別枠。絞り込み・検索 |
| `/favorites` | お気に入り記事 | ★ を付けた記事と、好みの傾向 |
| `/backlog` | バックログ | 未読の選定記事（自動で入る）と「後で読む」。残数の推移。未読30日で自動的に「見送り」（「後で読む」は除く） |
| `/articles` | 全記事 | 選定された記事の表（並べ替え・絞り込み・検索・ページ送り） |
| `/rejected` | 落選記事 | 落選した記事の表。「実はよかった」を付けられる |
| `/insights` | 分析 | トピックの内訳・話題の推移・効き具合（👍率など）・バックログ推移・情報源の成績。表でも見られる |
| `/settings` | 設定・運用 | 興味プロファイル（と履歴・修正案）・好みメモ・重み・しきい値・件数・費用の上限・情報源の切り替え・実行履歴 |

どのシートでも、記事を開くと詳細（整理記事・URL 一覧・メモ・壁打ち・点数の内訳。この順）が出る（URL の `?topic=ID`）。
承認待ちの修正案があると、最新トピックの上にバッジ（設定へのリンク）が出る。
ライト／ダーク（端末に追従、手動で切り替え可）、スマホ幅にも対応。

## 点数と選定
- 5観点（関心との一致・実用性・新しさ・信頼性・内容の深さ）を 1〜5 で評価する。初期の重みは 20/25/25/15/15
- 合計 = Σ 重み × (点数−1)÷4。公式の情報源の記事は +5 点
- 論文・発表・リリースは、「実用性」の代わりに「実務・事業への示唆の大きさ」で評価する
- 60点以上かつ関心が3以上なら選定。選定に入らず「新しさ・重要度」が5なら重大ニュース。それ以外は落選
- 採点時の重みを記事ごとに保存する。実装は `backend/app/services/scoring.py`

## 収集
- 情報源は `backend/config/sources.yaml`（RSS・サイトマップ・一覧ページ・Zenn・Qiita・Hugging Face・arXiv）。取れない情報源は `disabled_reason` を付けて止める
- 流れ: 候補を集める → 古い・重複・AI と無関係・対象外の言語・募集や公募の告知・一覧ページを除く → 上限（既定 200 件、画面の設定）まで公式を優先して残す → 本文を取る
- 募集・公募の告知と一覧ページは、タイトルが `config/scoring.yaml` の `exclude_titles`（正規表現）に当たれば集めない。サイトマップ・一覧ページ由来の候補は取得するまでタイトルが分からないので、取得後にも検査する。採点でも、記事でないページは全観点を 1 にする
- 本文は、全文（trafilatura で抽出）／概要のみ／失敗に分類して保存する。短すぎるページはブラウザ（Chrome）で取り直す
- 礼儀: robots.txt を守り、同じサイトへの同時接続・間隔を制限する（arXiv は 3 秒に 1 回・同時 1 接続）。ログイン・有料・確認画面（Cloudflare 等）は破らず、「全文未取得」とする
- 情報源に `fetch_body: false` を付けると、記事ページを取りに行かず、一覧（RSS）の概要だけで登録する（OpenAI News: 確認画面で本文を取れないため）。同じ話題の他媒体の記事があれば、その本文を採点の材料にする
- Brave Search は使わない（規約が検索結果の保存と AI の評価への利用を禁じるため）
- 実行は、画面の「更新」ボタン、または `make collect`。ボタンは実行の行（`runs`、実行中は1つまで。DB の部分一意インデックスで保証）を作り、`scripts/collect.py --run-id N` を別プロセスで起動して待たずに返る。出力は `data/logs/run-<id>.log`。落ちたときは「失敗」にして原因を実行履歴に残す。処理が生きている印（ハートビート）が10分止まった実行は、次に状態を見るときに「失敗」にする。進捗表示・途中停止はない（止まった分は次回の更新が続きから処理する）
- 実行は `make collect`。結果は情報源ごとの表（全文・概要・失敗・平均文字数・理由）と、まとめ・採点・選定の件数・費用で出る。`--no-llm` で Haiku を使わずに実行できる

## 話題のまとめ・採点・選定（Haiku）
- モデル: 実行のたびに最新の有効な Haiku を選ぶ（一覧を取れない・料金表にない新モデルのときは前回のモデルで続け、実行履歴に理由を残す）。使ったモデル名と指示文（スキル）の版は、点数と一緒に保存する
- 料金表は `backend/app/services/llm/pricing.py`（Haiku 5.5: 入力 $0.10・出力 $0.50／100万トークン）
- 費用の上限: 呼ぶ前に見込みを予約して「今回 $0.5」「今月 $10」（設定で変更可）と比べ、超えそうなら止める。残りの記事は次回に回る。実費は `llm_usage` に記録する
- 話題のまとめ: 同じ共通リンク（いまは arXiv ID）は Haiku を使わずまとめ、残りは Haiku が既存の話題（直近3日）と照らして判定する。迷ったらまとめない。代表は 公式 → 紹介記事 → 論文
- 採点: 代表のうち最大 `max_scored` 件（公式 → 新しい順）を、同時5件で1件ずつ採点する。指示文は `backend/skills/score/`（`SKILL.md`＋`rubric.md`）。出力の形は `app/schemas/analysis.py`
  - 全文を取れなかった代表は、同じ話題の他媒体の本文を材料に足す
  - 指示文の前半（スキル・基準・プロファイル・👍/👎）は固定してプロンプトキャッシュを効かせる
- 選定: `scoring.py` の判定のあと、点数の高い順に最大 `max_selected` 件。全文を持つ記事が1件もない話題（概要のみ）と、情報源に `digest: true` を付けた週刊ニュースレター（The Batch・Import AI・Latent Space）の話題は、重大ニュースにしない（しきい値を超えれば選定はする）。上限であふれた話題のうち「新しさ・重要度」が5のものは重大ニュースの候補（最大 `max_major` 件）。残りは落選
- 整理記事: 選定・重大の話題のうち未作成のものを、同時4件で1件ずつ Haiku が書く（効果量 `medium`）。指示文は `backend/skills/compose-<種類>/SKILL.md`（種類は announcement・howto・paper・analysis・industry）＋共通の `skills/_style.md`。出力は「3行まとめ」と「見出し＋段落（段落ごとに推測かどうかの印）」で、型は `app/schemas/analysis.py` の `DigestOutput`
  - 材料: 代表記事の本文（最大2万字）、本文のある関連記事（最大3件・各2万字）、興味プロファイル。論文の全文読み込みは未実装（要旨・序論・結論まで）
  - 読み手が「記事が言っていること」と「AI の意見」を区別できるようにする。記事が述べていること（記事自身の「〜の可能性がある」を含む）は、誰の発言かを示して書かせる。AI 自身の意見・予想・評価は、`inference: true` の段落にだけ書かせ、画面では「AI の意見」と色分けして表示する。URL は Haiku に書かせず、画面が DB の URL から一覧を作る
  - 校閲: 書いた直後に、別の Haiku（`skills/verify/`）が材料と照らして、各段落を「記事に書かれていること（article）」か「AI が付け加えたこと（ai）」に判定する。書き手と校閲の**どちらかが ai と判定した段落**を AI の意見として保存する（事実と表示されるのは両方が認めたもの。判定のない段落も AI の意見）。校閲に失敗したときは整理記事を作らず、次回に再試行する。費用は `llm_usage` に目的 `verify` で残る（1件あたり約 0.12 セント）
  - 長さの目安（論文は最大2,000字、他は800〜1,500字）は指示文で伝えるが、Haiku は字数を数えられないため守られない（実測: 1,150〜1,750字）
  - 失敗・上限停止のときは作らず、次回の更新で再試行する。作成後は全文検索の索引も更新する
  - 試し作り: `uv run python -m scripts.digest`（種類ごとに1件。収集はしない）
- 好みメモ・修正案（フィードバックループ）: 前回の好みメモより後に付いた評価（👍/👎/実はよかった）が20件以上たまると、更新の最後に Haiku を1回呼び（`skills/preference/`）、好みメモ（800字まで）を書き直し、興味プロファイルの修正案（追加・削除・言い換え、最大3件）を出す。修正案は自動では反映せず、承認・編集して承認・却下を画面で選ぶ
  - 出力は確かめてから保存する: 「変更前の文」がプロファイルにそのまま無い案、すでにプロファイルにある追加、根拠が評価済みの話題でない案は捨てる。却下した案と同じ内容は30日出さない（同じ種類の別の内容は出す）。未決が3件あるときは増やさない
  - 承認時にも「変更前の文」を確かめ、合わなければ 409（プロファイルが変わったため）。プロファイルは変わるたびに履歴（`profile_versions`）へ追記し、古い版に戻せる
  - 好みメモは、採点の指示文に（興味プロファイルの次に）入る。採点に使った評価の話題 ID は実行（`runs.feedback_topic_ids`）に記録する。実測: 好みメモありで採点した差は平均 -1.0 点・最大 6 点で、採点のぶれ（平均 4.8 点）の範囲内
  - 試し作り: `uv run python -m scripts.preference [--force]`（収集はしない）
- 壁打ち: 詳細画面の整理記事の下で、その話題について Haiku に質問できる（`skills/chat/`、`app/services/chat.py`）。Haiku が読み取り専用のツール4つ（記事の本文・関連記事・過去記事の検索・★の記事の検索）を、必要なときに自分で呼ぶ（1回の回答で6回まで。検索語は空白で区切った語ごとに探す）。最初に整理記事と代表記事の本文を渡す。履歴は話題ごとに保存し、回答には使ったツールの記録を添えて次の質問に渡す
  - 1回の回答の費用の上限は $0.05（月の上限 $10 も守る）。実測は1回約 0.2 セント。費用は `llm_usage`（目的 `chat`）に残り、今月の費用に入る。上限で答えられなかったときは、その旨を回答として保存する
  - 回答は文章として表示する（HTML は描画しない）。記事の発言は誰の発言かを示して書かせ、AI 自身の意見は「（AI の意見）」の行に分ける（画面で色分け）。回答に校閲はなく、守られない場合がある
  - 回答を「メモに残す」と、整理記事の下に出る。メモは全文検索の対象
- 点数のぶれの検査: `uv run python -m scripts.score_variance`（同じ記事を複数回採点して差を見る）

## データ（DB）
`sources`・`topics`（話題。あなたの操作の状態も持つ）・`articles`・`article_texts`（本文）・`scores`（5観点・そのときの重み）・
`digests`（整理記事）・`chat_messages`・`notes`（壁打ちとメモ）・`preference_notes`・`profile_proposals`・`profile_versions`（好みメモ・修正案・プロファイルの履歴）・`runs`・`run_issues`・`search_queries`・`llm_usage`（Haiku の費用）・`settings`。
日時は UTC で保存し、表示のときだけ日本時間にする。全文検索は SQLite の FTS5（`topic_search`）。
表の形の変更は Alembic（`backend/alembic/`）。
