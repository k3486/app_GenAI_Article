# 生成AI記事ダッシュボード（段階①：ローカル版）

## 目的
生成AIの記事を Web から集め、上司の好みで選定し、関心に沿って整理した日本語の記事とともに、ダッシュボードで可視化する個人用アプリを作る。
まずローカルで動かしてデザインと動作を確かめる（段階①）。Web 化（②）と、共通部品の雛形への返却（③）は別の作業とする。

## やること（段階①）
- 7シートのダッシュボード: 最新トピック／お気に入り記事／バックログ／全記事（選定済み）／落選記事／分析／設定・運用
- 記事の収集（RSS・公式サイトの一覧・Brave Search・HF Daily Papers・arXiv）と全文の取得（robots.txt 遵守）
- Haiku による採点（5観点）・同じ話題の判定・検索語の生成・整理記事（5種類の構成）
- 壁打ち（記事ごとの対話、エージェント）
- フィードバックループ（👍👎・「実はよかった」→好みメモ→プロファイルの修正案）
- 費用の管理（月 $10・1回 $0.5 の上限、使用額の表示）

詳細は `design.md`（承認済みの計画）。

## やらないこと（この作業では）
- Web 化（AWS の構成、ログイン、Docker、定時実行）→ 段階②
- 共通部品の app-template への返却 → 段階③
- 過去記事の再採点、週次ダイジェスト、探索枠、埋め込みによる意味検索、壁打ちでの Web 検索
- 原文のアプリ内表示（本文は DB に保存するが表示しない）

## 完了条件
- `make lint && make test` が通る
- 確認ゲート G1〜G5（`design.md` の「確認ゲート」）を、上司の確認つきで通過する
- 本物の記事で1回以上更新し、本文の取得率・採点の質・記録された費用を確認できている
- `docs/spec.md`・`docs/architecture.md` が現在の仕様に更新され、`history.md` に追記されている
